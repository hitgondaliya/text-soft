Gopika (Oasis Systems 1993) was wired for Gujarati on 2026-09-14. Its byte
layout is the **ITR typewriter scheme**: comparing the font's own glyphs against
all 21 Gujarati keyboards we ship, `guj-itr.json` matched 17/17 letter keys and
every other layout matched 0-1. That trick — *a legacy font's byte assignment is
the keyboard it was drawn for* — is the fastest way to identify any unknown
legacy font, and beats shape matching, which scored only 34/183 here.

The table (`assets/config/mappings/*gopika-guj*.json`, generated by
`tools/GopikaMap`) is ~105 atoms plus regex reorder rules, not an enumerated
cluster list, because there is no reference converter to capture from. Places
where the font differs from the ITR key chart: ળ=0xA4, શ્ર=0xA7, પ્ર/ક્ર/ફ્ર=0xA1-A3,
half forms ્મ/્ય/્ન/્ત = B/G/L/0xC0, nukta = `|`, and `#`/`$` are ઇં/ઈં rather than
ઙ/ઞ. ઙ, ઞ and ૠ have no glyph at all and are declared in `encoding-limits.json`.

Conjuncts without a ligature byte fall back to consonant+virama+consonant, which
is what the typewriter does; the high-byte ligature area (0xB0-0xFF, mostly
દ્ધ/દ્ય/હ્ય style forms) is still unmapped and is the obvious next refinement.
See [[textsoft-coverage-status]] and `tools/GopikaMap/NOTES.md`.
